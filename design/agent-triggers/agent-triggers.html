Start an agent

When a note arrives, Fruitback can call an address of your team, which starts your agent: a receiver that dispatches a workflow of GitHub that runs Claude Code, or a cloud agent. The call carries the id of the note, never its text: the agent reads it through the MCP server, with its agent key.

B · On: the address, the moment, what the call carries

  • The address is one of the workspace that receives (the REST connector, FRU-132): signed with its secret, tried again, its failures in its panel. No new address field, no second queue (agents.md: what was set aside).
  • Two moments, one at a time: a note of a known person (default, decision 4), or a person of the team who moves a note to To do. The second reads only the notes that Fruitback keeps, and an agent key never starts it, so an agent cannot start itself.
  • « What the call carries » shows the body: ids, never the text nor the files. The agent reads the note through /mcp with its key.
  • One « Save » for the section: the switch, the address and the moment are one setting of the site, written in one request.

Decisions of the board (fru-agents, 2026-10-28)

The orchestrator asked the agent to decide the choices itself and to write them down. Each one can be changed by Mathieu.

  1. Where. A section of the page of a site, « Start an agent », after « Statuses ». A trigger is of a site (agents.md); a page of its own would be one more place for one setting.
  2. Who. The owner and the admins (manage-workspace), as for the agent keys: the call starts a process of the team, with its rights.
  3. The address is a REST connector of the workspace. It is already signed, tried again, guarded against a private address at each attempt, and its failures are in its panel with « Try now ». The section chooses one; with none, it leads to Connectors. A site that also sends its notes to the same address gets two calls for a note: note.created and agent.requested, told apart by event.
  4. The body: version 2, event: "agent.requested", reason (verified-note or moved-to-todo), the workspace, the site, the identifier and note.id, the id that get_feedback takes. No text, no file, so nothing of the note leaves twice.
  5. GitHub. Fruitback holds no token of GitHub: repository_dispatch needs one. The team's receiver checks the signature and calls repository_dispatch with its own token; docs/agents.md gives one, short. The other ways (a token of the team kept by Fruitback, or the right contents: write on the GitHub App) are a new secret or a new permission of the manifest: not taken.
  6. The two moments, one at a time. A verified note (a member, or a reviewer the site's identity verified), or « moved to To do » by a person with a session of the console or the extension, on a note that Fruitback keeps. An agent key that sets a status never starts a call: an agent cannot start itself.
  7. One call per note and moment. A note moved to To do twice calls twice only if it left To do between; a note of a known person calls once.
  8. One « Save ». The switch, the address and the moment are written together.
  9. The real trial (a repository_dispatch that runs a workflow reading the note by /mcp) needs a worker reachable from GitHub and a receiver deployed: an environment of Mathieu, not of an agent.
